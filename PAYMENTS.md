Покупка доступна **только на сайте**. Android показывает тариф и полученный доступ, но не открывает внешнюю оплату. Сайт и приложение используют один серверный профиль. Реквизиты, условия оплаты и возврата и обработка данных опубликованы на `/contacts`, `/terms` и `/privacy`.

Владелец указал статус самозанятого. По [инструкции ЮKassa о чеках](https://yookassa.ru/developers/payment-acceptance/receipts/basics) самозанятый регистрирует доход в «Мой налог» и передаёт чек покупателю; ЮKassa не делает это за него. Поэтому Сметра **не отправляет `receipt` по схеме 54-ФЗ** в запросе платежа. В административной панели видны последние платежи и адреса покупателей для ручной сверки. Отметок об отправке чеков в системе пока нет: владелец сверяет платежи в кабинетах ЮKassa и «Мой налог» и вручную обрабатывает возвраты по налоговому учёту.

Сервер принимает checkout только при `YOOKASSA_MODE=test` или `live`, наличии `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` и явном `YOOKASSA_MERCHANT_TYPE=self_employed`. В тестовом режиме доступ к checkout имеет только подтверждённый аккаунт `YOOKASSA_TEST_EMAIL`; остальные пользователи видят отключённую покупку. При создании и подтверждении платежа сервер проверяет магазин (`recipient.account_id`), признак `test`, сумму, валюту, пользователя, тариф и `paid=true` для успеха. После webhook сервер сам запрашивает объект у ЮKassa; тело уведомления не выдаёт доступ. Повторные уведомления не продлевают тариф. Полный возврат отзывает соответствующий доступ. Подход к проверке уведомлений соответствует [документации ЮKassa](https://yookassa.ru/developers/using-api/webhooks).

Для завершения подключения:

1. В кабинете боевого магазина укажите webhook `https://smetra.vercel.app/api/webhooks/yookassa` для `payment.succeeded`, `payment.canceled`, `refund.succeeded`. По [документации ЮKassa](https://yookassa.ru/developers/using-api/webhooks), при HTTP Basic Auth это настраивается в личном кабинете.
2. Проведите контрольную оплату подтверждённым аккаунтом. Сверьте магазин, сумму, тариф и выдачу доступа на сайте и Android. Оформите чек в «Мой налог» и передайте покупателю.
3. Проверьте отмену и возврат; для возвращённого платежа доступ отзывается после синхронизации. Частичный возврат требует ручного разбора.
4. При возможности заведите отдельный [тестовый магазин](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) для регулярных безопасных проверок. Не заменяйте боевые переменные тестовыми на Production.

У аккаунта должен быть подтверждённый адрес почты. Сейчас на сервере нет SMTP, поэтому оплата через обычную регистрацию по почте недоступна до подключения писем. Проверенный вход через OAuth может дать подтверждённый адрес. Учётные данные демонстрационного аккаунта для проверки сайта передавайте проверяющим отдельно; этот аккаунт не должен иметь административный доступ и не используется для реальных платежей. Боевой shopId и ключ проверены read-only запросом к API ЮKassa; контрольный платёж, webhook и чек ещё нужно проверить. Тесты используют локальный двойник ЮKassa и не заменяют эти проверки.


## B2B тарифы и автопродление

Публичный каталог фиксирован и одинаков для всех пользователей: `pro_month` — 490 ₽/мес, `pro_year` — 4 900 ₽/год, `pro_plus_month` — 690 ₽/мес, `pro_team_month` — 3 990 ₽/мес и `pro_team_year` — 39 900 ₽/год. Годовые цены не управляются старым A/B-тестом или переменными окружения. TEAM включает владельца и до четырёх сотрудников (пять мест всего).

Автопродление выключено по умолчанию. Чтобы его включить, магазин должен поддерживать сохранение платёжного метода; клиент должен отдельно согласиться на рекуррентные списания, а backend сохраняет версию и время согласия. Первый checkout отправляет `save_payment_method=true` только при явном согласии. После подтверждённой оплаты ID сохранённого метода хранится на сервере. Повторное списание выполняет `/api/cron/billing` по сохранённому `payment_method_id`; ежедневная задача использует `CRON_SECRET` и стабильные ключи идемпотентности, а состояние попыток хранится в `billing_renewal_attempts`. По умолчанию `YOOKASSA_RECURRING_ENABLED=0`; включать флаг можно только после подтверждения допуска автоплатежей у YooKassa и проверки на тестовом магазине. Задача Vercel запланирована один раз в день, она не запускается, пока нет секретного ключа и явного флага.

Контакты заявок хранятся отдельно от публичных карточек. Доступ к контактам включён в активную PRO Solo, PRO Плюс или TEAM-подписку и выдаётся через идемпотентную запись `lead_access_grants`. Новые покупки отдельных пакетов токенов и открытие контактов за токены закрыты. Исторические транзакции остаются для сверки и возвратов. Поля CPA в `affiliate_clicks` готовы для будущего 3% вознаграждения; автоматическое подтверждение заказов партнёрами и выплаты пока не подключены.


## Rewarded-реклама и лимит бесплатного ИИ

Rewarded-реклама остаётся выключенной до подключения серверно проверяемого подтверждения награды. Android callback и одноразовый nonce не являются доказательством просмотра для backend, поэтому endpoint не начисляет награды только по данным клиента. Не устанавливать `REWARDED_ADS_REQUIRED=1`, пока не будет реализована и протестирована доверенная проверка.
