# Повтор загрузки и создания диалога — Android 1.7.6

При потере ответа после сохранения файла или создания диалога повторная попытка
с тем же ключом возвращает прежний ID. Одновременные запросы сериализуются в
существующей транзакции записи. Повтор с изменённым содержимым получает 409;
удалённый результат также получает 409 и не создаётся заново.

Ключи разделены по пользователю, рабочему пространству и типу операции. В базе
хранятся SHA-256 ключа и запроса, ID результата и время; содержимое файла туда
не дублируется. Таблица `smetra.creation_requests` имеет RLS и FORCE RLS,
изолирована по действующей сессии и рабочему пространству. Runtime может только
читать и добавлять записи; UPDATE/DELETE ему не разрешены. Anon/authenticated
не имеют доступа к таблице. Проверка действующих прав остаётся перед повтором.

Android сохраняет ключ операции вместе с состоянием выбора файла. Повтор после
потери ответа или пересоздания Activity использует тот же ключ для файла и нового
диалога. Явный выбор другого файла начинает новую операцию. Веб-чат сохраняет
ключ неудавшейся загрузки в sessionStorage, отдельно по аккаунту, пространству
и диалогу, и сверяет SHA-256 выбранного файла. Перезагрузка страницы не создаёт
дубликат при повторном выборе того же документа. Двойная загрузка из drag/drop
во время текущей операции блокируется.

## Границы

Защита работает при переданном ключе операции. Старые клиенты без ключа сохраняют
прежнее поведение. Веб хранит ключ до успеха или явного конфликта в текущей сессии
браузера. Очистка sessionStorage либо новый выбор в APK начинает новую операцию.
Публикация новой версии в RuStore и проход на физическом телефоне ещё не выполнены.
Фоновые OCR/индексация/импорт и поиск изображений остаются отдельными задачами.
