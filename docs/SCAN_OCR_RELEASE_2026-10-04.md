# OCR сканов PDF · 1.7.9

В чате можно прикрепить PDF без текстового слоя, дождаться проверки документа
и нажать «Распознать скан». Первые две страницы распознаются в фоне; результат
сохраняется в приватном индексе для чтения и поиска ассистентом. Исходный PDF
остаётся без изменений. При возвращении на экран видны статус, квота и отметка OCR.

- Отдельная квота документов: 3 в месяц на «Старт», 30 при действующем «Про».
  Месяц считается в UTC, как в существующих квотах. Чат и чеки имеют свои квоты.
- Не более двух активных OCR-задач пользователя в рабочем пространстве;
  до трёх попыток при временной недоступности бесплатной модели. Платные модели запрещены.
- Ошибка и отмена возвращают резерв один раз. Повтор готового документа
  использует индекс и не создаёт новый расход. Непрочитанный скан не расходует сообщение.
- PDF до 5 МБ в обработчике; загрузка через production API ограничена 3 МБ
  из-за транспортного лимита Vercel. До 100 страниц в PDF, распознаются первые 2.
  При пропуске остальных страниц или нечитаемой странице результат помечается частичным.
- PDFium работает в отдельном процессе без учётных данных: предел памяти
  384 МБ, CPU 15 секунд, ожидание 25 секунд. Проверка структуры PDF отклоняет
  активное содержимое. Изображения ограничены 1600 px и 1,5 МБ; ответы модели — 6000 символов на страницу.
- Текст и завершение задачи сохраняются одной транзакцией после повторной
  проверки сессии, роли, исходного SHA-256, lease и отмены. Частичный индекс при ошибке не публикуется.
- Сайт сохраняет черновик вопроса в sessionStorage отдельно для аккаунта,
  рабочего пространства и диалога/контекста. Ошибка и переходы его сохраняют;
  успешная отправка очищает только соответствующий черновик. Новый диалог начинает с пустого поля.
- Android использует нативный интерфейс, а не WebView сайта. OCR-статус встроен в блок файла.

Проверки: 246 backend-тестов, один пропущен; 10 отдельных сценариев OCR
(реальный рендер скана, лимит страниц, квота, параллельный повтор, приватность,
отмена между страницами, ошибки, смена источника, отзыв сессии и потеря lease).
Ruff и аудит зависимостей прошли. Браузер 390 px: сохранение вопроса при OCR,
переходах и перезагрузке, отдельный новый диалог, отсутствие горизонтального переполнения.
Нативный сценарий на Android 35: выбор скана, запрет отправки до распознавания,
фоновая обработка, возвращение к черновику, OCR-квота и потоковый ответ по файлу.

Production: реальная цепочка Supabase cron → Vercel → изолированный PDFium
→ бесплатная vision-модель → SQL-индекс прошла с первой попытки. На синтетическом
трёхстраничном скане прочитаны первые две страницы с контрольным текстом и суммой,
результат помечен частичным. API и runtime RLS закрывают данные от второго аккаунта;
чатовая квота не потрачена. Временные production-аккаунты и их данные удалены.
Миграция 26 расширяет закрытую очередь и собственную OCR-квоту; публичные права не добавлены.

Ограничения: OCR может ошибаться; суммы и реквизиты требуют проверки по оригиналу.
Точность на реальных документах и физических телефонах ещё не оценена.
Многостраничный OCR сверх первых двух страниц, смешанные PDF и конвейеры импорта
остаются отдельной работой. Не считать все прежние ТЗ полностью закрытыми.
