# Пять систем «Сметры»: первый интеграционный backend-релиз

Статус: 24 октября 2026. Область: API, PostgreSQL, проверка прав, математический движок.
Интерфейс Android/Web для новых маршрутов и реальный LiDAR/камера-инструмент — отдельный этап. Продукт нельзя считать полностью готовым без мобильной интеграции и E2E на устройствах.

## 1. Голосовая смета

POST /api/voice/draft (авторизованный пользователь с доступом к рабочему пространству).
Тело: {"format":"wav|mp3|flac","audio":"base64"}.
Ограничения: аудио <=1,4 МБ; только известные сигнатуры; до 3 попыток за 5 минут; аудио не сохраняется.
OpenRouter Speech-to-Text: /api/v1/audio/transcriptions с model openai/whisper-large-v3 и language ru.
Полученный текст подаётся в уже существующий AI-draft: строгая JSON-схема, максимум 30 позиций,
неизвестные цены равны нулю, подсчёты выполняет только backend.
Ответ: {"draft": {...}, "transcript":"...", "requires_review":true, "audio_retained":false}.
Никаких финальных сумм от LLM и автопубликации.

## 2. AR-обмеры

POST /api/construction/objects/{object_id}/scan/preview
POST /api/construction/objects/{object_id}/scan/import
Тело: {"rooms":[{"name":"Ванная","length":"4","width":"3","height":"2.5","unit":"м",
"openings_m2":"2","mix_kg_per_m2":"1.2","bag_kg":"25","waste_percent":"10"}],
"review_confirmed":true} для импорта.

Все вычисления на Decimal: площадь пола L*W, периметр 2*(L+W), общая площадь стен P*H,
чистая площадь = P*H-openings, материал = чистая площадь * кг/м² * (1 + запас/100),
количество мешков округляется вверх.
Запрет отрицательной чистой площади, размеры 0,5–100м, не более 12 помещений за запрос.
Превью не изменяет БД. Импорт атомарно создаёт зоны, запускает пересчёт зависимых количеств,
сбрасывает привязку к опубликованной смете, требует согласия пользователя.
Это импорт данных обмера, а не самостоятельная AR-камера/SDK.

## 3. Разбор PDF

POST /api/design-projects/draft, тело:
{"file":{"name":"project.pdf","mime":"application/pdf","content":"base64"},"instructions":"опционально"}.
Общий проверенный AI capture_file принимает PDF до 2MB/12 страниц, извлекает текст (pypdf),
передаёт его нейросети как недоверенный ввод и валидирует строгую схему.
Возвращает только проверяемый черновик для ручной проверки; хранение и публикация
не происходят автоматически. Отсканированный PDF без текстового слоя требует отдельной OCR-ветки,
поскольку существующий OCR-процесс строится для приложенных файлов.

## 4. Отправка смет и привлечение клиентов

POST /api/shares; тело {"quote_id":"UUID","email":"client@example.org"}.
Обязательные условия: подтверждённая почта отправителя, роль owner/admin/manager,
опубликованная и действующая смета, лимит отправлений и лимит адресата (3/сутки).
Клиент с подтверждённым email получает адресное push-уведомление и видит документ
в /api/shared-inbox. Новый клиент получает email через VK WorkSpace со ссылкой
/app?share={share_id}, затем входит/регистрируется с той же почтой.
Таблица estimate_shares привязана к неизменяемой версии published_version, email и сроку.
GET /api/shares показывает исходящие приглашения, GET /api/shares/{id} —
статус ответа, DELETE /api/shares/{id} отзывает доступ.

ВАЖНО: отправка email на текущем этапе синхронная и ограничена 12-секундным SMTP timeout.
Для большой нагрузки требуется отдельная надёжная очередь исходящих писем, idempotency
и наблюдаемость доставки. В frontend пока нет отдельного экрана приглашённых смет.

## 5. Выбор и согласование

GET /api/shared-inbox: только предложения для подтверждённого адреса пользователя.
GET /api/shared-inbox/{id}: редактируемый просмотр необязательных строк
в опубликованной версии, только публичные поля; себестоимость скрыта.
POST /api/shared-inbox/{id}/selection, тело:
{"revision":0,"included_optional":[1,3]}; нулевая индексация элементов.
Итоги рассчитываются по сохранённым позициям математическим движком (цен с клиента нет).
POST /api/shared-inbox/{id}/approve, тело:
{"revision":1,"action":"approve|request_changes"}.
Если сумма совпадает с опубликованной и пользователь нажал approve —
смета переводится в approved, отправитель получает push. Если пользователь убрал
необязательную позицию — создаётся changes_requested и пуш без изменения исходной цены.
Повторное подтверждение или устаревшая версия получают 409.

Отчёты ответов хранятся в estimate_share_responses, включены ENABLE/FORCE RLS.
Роль smetra_runtime имеет только SELECT с привязкой к проверенному рабочему пространству.
Роли anon и authenticated не имеют прямого доступа. Ответ клиента выполняется через
серверный API после проверки сессии, verified-email и опубликованной версии.

## Нагрузочные ограничения и следующий этап

- SMTP-рассылка должна перейти на durable outbox с арендой задач, повторными попытками,
  idempotency и квотированием провайдера.
- Аудио должно загружаться чанками или напрямую во временное хранилище с TTL на мобильном интернете.
- PDF с отсканированными чертежами требует OCR worker и привязки результата к страницам.
- AR требует интеграции Android ARCore/совместимого SDK и ручной верификации геометрии.
- Добавить интерфейс голосового ввода, помещения, PDF-очереди, отправки и кабинета клиента.
- Проверить реальные OpenRouter вызовы, доставку VK WorkSpace, RuStore-пуши и параллельные ответы
  на staging. Тесты не доказывают готовность к 300000 MAU.
