# Модернизация «Сметры»: план этапов

Каждый этап — отдельные небольшие коммиты с тестами. Финансовые, миграционные и
необратимые изменения сначала описываются здесь и согласуются.

## Этап 1. Аудит и критические ошибки — сделано

| Проблема | Причина | Исправление |
|---|---|---|
| «Не удалось обновить статистику: Внутренняя ошибка» | `billing_subscriptions` не была в списке таблиц PostgreSQL-адаптера, запрос шёл без схемы `smetra` | Таблица зарегистрирована, тест проверяет все таблицы модуля |
| ИИ отвечал, что не может создать смету | Закреплённая модель OpenRouter отдавала 404, запрос падал до режима без инструментов; описание инструмента было «Предложить создание quotes» | Модель → `openrouter/free`; инструменты описаны по-русски; правило «создание сметы — штатная задача»; аварийный режим не утверждает, что не умеет |
| Кнопка «Смета» в ассистенте только писала подсказку | Без выбранной сметы ничего не открывалось | Кнопка «Сметы»: список смет → предпросмотр, «к списку», закрытие |
| Центр общения закрывал сайдбар и шапку | `position:fixed; inset:0` поверх всего | Страница внутри кабинета, папки переносятся |
| Очередь поддержки без статусов | Только флаг «нужен сотрудник» | Статусы Новое / В работе / Ожидает пользователя / Решено (вычисляются из данных, без миграции), «Взять в работу», передача сотруднику, «Решено» |
| Окно «Память»: обрезанные кнопки | Форма не помещалась на низких экранах | Липкая панель действий, компактная шапка |
| Админка: кнопка очереди, поиск «⌕», «Управлять» | Класс на ячейке вместо кнопки, текстовый глиф | SVG-иконки, выравнивание, пагинация |

## Этап 2. Безопасность (план)

- TOTP 2FA (RFC 6238) для пользователей и обязательная для администраторов.
  Нужна миграция: `user_mfa(user_id, secret_encrypted, enabled_at, recovery_hashes)`.
  Секрет шифруется ключом из окружения, коды восстановления — только хеши.
- RBAC: роли `owner/admin/support/finance` вместо одной `admin`; проверка на сервере.
- Журнал аудита уже есть (`audit`) — добавить фильтры и экспорт в админке.

## Этап 3. Сметы через ассистента

- Удаление сметы в корзину (`quotes.deleted_at`, восстановление 30 дней) — миграция.
- Инструмент `delete_quote` только с подтверждением; итоги считает сервер.

## Этап 4. ИИ-поддержка с диагностикой

- Серверные инструменты только для чтения: статус платежа в ЮKassa по id,
  состояние подписки, последние ошибки входа. Никакого SQL от ИИ.
- Восстановление доступа — только идемпотентная функция по подтверждённому
  платежу ЮKassa (`succeeded` от API, не скриншот), с записью в журнал решений.
- Эскалация человеку, если API не подтвердил оплату.

## Этап 5. Экономика ИИ-кредитов — нужно согласование

Текущая модель (лимиты сообщений по тарифу) не меняется до отдельного решения.
Предложение: кредиты = стоимость токенов модели × коэффициент, списание после
ответа по фактическим `usage`, предоплата резервом. Требует миграции и
изменения тарифов — без согласования не внедряется.

## Этап 6. Мессенджер

Realtime (SSE), ответы на сообщения, правка/удаление, статусы прочтения,
вложения через существующее файловое хранилище, затем голос и видеокружки.

## Этап 7. UI/UX

Страница лидов, файлы с квотой «Использовано: X МБ из Y», калькуляторы,
OTP-ячейки со статусами проверки сервером, адаптив.
