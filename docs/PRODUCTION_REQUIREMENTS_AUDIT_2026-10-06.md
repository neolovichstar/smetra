# Проверка ТЗ от 6 октября 2026

Источник: документ из вложения `29060086-c0ee-430e-9ebb-089475cc0ea2`, разделы 0–69. «Есть» означает наличие реализации и указанных проверок; это не подтверждение каждого подпункта большого раздела. Непроверенные внешние операции и отсутствующие функции перечислены отдельно.

## Архитектура

Это существующий проект: `apps/web` — обычный JavaScript/CSS, Python API в `backend`, PostgreSQL в закрытой схеме `smetra`, SQLite для локальных тестов, Redis REST для распределённых ограничений и задач. Android — собственный нативный Java-интерфейс, а не WebView сайта. Next.js, React, TypeScript, package.json и их проверки неприменимы к текущему стеку. Статическая сборка проверяет JavaScript через `node --check`; Python проверяется Ruff, compileall и unittest; Android — Gradle и Android Lint.

## Реальные неисправности и изменения

- Все запросы APK выполнялись в одном потоке вместе со стримингом и загрузками файлов. Обычный API перенесён в отдельную очередь из двух потоков. Ответ привязан к исходной сессии и экрану; завершившийся после выхода запрос не возвращает старые данные и не записывает их в локальный кэш.
- Отложенные стримы, файлы и остальные долгие операции APK теперь используют исходную сессию даже внутри вложенных запросов. Очередь пропускает задания после смены аккаунта; ответы старой сессии не меняют новый интерфейс. Загрузка вложений не возвращает пользователя на уже закрытый экран. Проверено настоящим Java Executor с контролируемой задержкой и сменой аккаунта во время выполнения.
- Начальный экран сайта загружал ассистент, Markdown, объекты, админку и профиль независимо от открытого раздела. Теперь эти модули загружаются по необходимости с повторяемой загрузкой после сетевого сбоя. Кнопка «Спросить AI» сначала загружает ассистента, затем передаёт контекст выбранной записи.
- Декорирование кнопок повторно обходило весь экран при обновлении DOM. Теперь обрабатываются только добавленные поддеревья, с объединением работы в animation frame.
- `ensure_workspace` выполнял две конфликтующие вставки даже при чтении существующего рабочего пространства. Для существующего владельца и членства используется чтение; восстановление отсутствующих записей осталось идемпотентным.
- Одновременные одинаковые GET объединены только внутри одной сессии, пользователя и пространства. Завершённые ответы не сохраняются в общем кэше; запись сбрасывает объединение ожидающих чтений. Добавлены таймауты и понятные сообщения о сети.
- Поздняя загрузка редактора/просмотра Markdown могла заменить уже открытый другой экран. Добавлены проверки поколения, пользователя и страницы до и после асинхронных операций.
- Локальный Python-сервер не отдавал Onest, `theme-init.js` и `themes.css`. Добавлены маршруты и проверка всех начальных ресурсов кабинета.
- Поля профиля на телефоне стали одноколоночными; длинный текст не сжимается. Упорядочены межстрочные интервалы, переносы и подписи. Убраны анимируемые размытия диалогов на мобильных экранах.
- По мобильному скриншоту обнаружено наложение контекста композера на статус фонового распознавания. Переписка, действия и задачи перенесены в отдельную прокручиваемую область; композер занимает собственное место. При потоковом ответе прокрутка следует за текстом только если пользователь остаётся у конца переписки.
- Суммы общего кабинета сохраняют копейки. Предпросмотр строк сметы переведён на целочисленную десятичную арифметику BigInt с тем же округлением, что у серверного Decimal. Добавлены пределы числовых полей; некорректная цена отмечается в поле.
- Регистрация по почте не предлагается на production без работающей доставки писем. Доступные OAuth-сервисы остаются способом создания профиля; существующий вход по почте сохранён. Возможности сообщает сервер, сайт и APK используют одинаковый признак.
- В окружении Vercel Production обнаружен ранее включённый `ALLOW_UNVERIFIED_SIGNUP`; установлен `0` и опубликована новая сборка. Рабочий `/auth/providers` подтверждает отключённую регистрацию по почте и включённый Яндекс ID. Существующие аккаунты сохранены.
- Добавлены manifest и service worker. Cache Storage хранит только общедоступный экран отсутствия сети и его CSS. Ответы API, документы, пользовательские страницы и POST не кэшируются этим механизмом.

## Проверки

- Сервер: набор из 303 тестов прошёл, один пропуск относится к PostgreSQL-only сценарию локального SQLite набора. [CI 37415703491](https://github.com/neolovichstar/smetra/actions/runs/37415703491) прошёл вместе с полным набором браузерных сценариев, проверкой PWA, Java-проверкой смены сессии и Android Debug/Release Lint. Дополнительно проверено, что композер ассистента не перекрывает область переписки и последнюю фоновую задачу на всех восьми ширинах 320–1440 px.
- Изолированный DOM: переносы экрана при медленной сети, офисные документы, композер, кнопки настроек, регистрация, транспорт API и 221 пользовательское действие.
- Предпросмотр денег: 156 вычислений сравниваются с настоящим `backend.business.calculate`, включая половину копейки, налог и исключённые опции.
- Android: release `1.7.17`, code `29`, `ru.smetra.mobile`, Android Lint и подписанная сборка прошли. `1.7.17` установлена на QA-эмулятор без удаления данных; экран входа запускается. SHA-256 финального APK: `D9D852C8548F51ED2F70D76380188D5461BBCC8F86B03D486D9D5918421911E6`.
- Production API: профиль/память CRUD, изоляция двух аккаунтов и очистка созданных тестовых записей прошли. Старый production до ускорений: медианы пустого аккаунта 234–358 мс по проверенным GET; это небольшой функциональный замер, не нагрузочный benchmark.
- После публикации повторный production CRUD и изоляция прошли, временные аккаунты удалены. Медианы проверенных GET нового замера: 252–345 мс; заметное ускорение самого API этим малым замером не подтверждено. Подтверждённое уменьшение начального JavaScript: 411 125 → 164 985 байт до сжатия (59,9%). Оно относится к загрузке/обработке интерфейса, а не к серверной latency. 34 опубликованных ресурса сверены с исходниками; закрытые маршруты без входа возвращают 401.
- Browser CI проверяет основной Client → Estimate → Share → Approval → Project → Recorded Payment → PDF, native Android build, отдельные экраны ассистента/знаний/профиля, ширины экранов и доступность ресурсов. Новый service worker отдельно проверяется с отключённой сетью.
