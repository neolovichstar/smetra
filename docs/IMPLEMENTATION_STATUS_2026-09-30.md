# Сметра: проверенное состояние на 30 сентября 2026

Это технический журнал проверок, а не заявление о полном завершении всех ТЗ.

## Обновление 1 октября 2026

- Справочник расценок получил отдельный web-экран, категории, избранное, поиск по названию/категории/артикулу и историю цены с номером версии. Редактор сметы ищет расценки на сервере и показывает избранные первыми. Вставка таблицы из Excel (до 200 строк) преобразуется в атомарный CSV-импорт; при ручном создании похожей позиции требуется явное разрешение дубликата. PostgreSQL миграция 18 применена: история цен изолирована по workspace через FORCE RLS, прямые grants для `anon`/`authenticated` отсутствуют. Локально прошли 156 Python-тестов (1 пропущен), Ruff, web build и браузерный сценарий на desktop/mobile. Production smoke ожидает развёртывания этой версии.
- В строительной ведомости добавлена массовая смена расценок на выбранные позиции: серверный предпросмотр суммы, проверка устаревших данных, применение и откат в течение 7 дней. Исходная отправленная клиенту смета сохраняется, связь объекта с ней сбрасывается, чтобы новую цену не выдать за уже согласованную. Миграция PostgreSQL 17 применена с FORCE RLS; production smoke прошёл полный цикл и удалил временный аккаунт. В редакторе обычной сметы появились выбор до 50 строк, предпросмотр общей суммы и локальный откат изменения коэффициента, наценки, единицы или категории до сохранения. CI `9e65082` и локальный мобильный браузерный сценарий прошли; Vercel deployment `dpl_21bzfxj6rZ3P4tQXnbMKCwhCPRZJ` готов.
- Локальный сервер исправлен: `construction.js/css`, `ai-workspace.js` и `file-editor.js/css` теперь выдаются по HTTP 200. Полный набор — 152 теста (1 пропущен), Ruff, web build и CI браузер/Android.
- OCR чеков теперь использует собственную настройку `OPENROUTER_OCR_MODEL` (по умолчанию `openrouter/free`), поэтому выбор модели текстового ассистента не ломает vision-запросы. Запрос просит итог чека, отключает расход короткого ответа на reasoning и сохраняет проверку результата человеком. Локальный тест подтверждает возврат месячной попытки при ошибке провайдера; полный набор — 148 тестов (1 пропущен), Ruff. Синтетическое фото в живом OpenRouter распознавалось нестабильно, включая неверный выбор цены позиции вместо итога: точность на реальных чеках не подтверждена.

- Для внутренних Markdown-документов добавлена история последних 10 состояний файла (до 100 исторических записей на workspace), просмотр и восстановление из редактора. Восстановление проверяет SHA-256 текущего файла и повторно индексирует содержимое для поиска. Чужие версии не читаются. Локальный сценарий создания, конфликта, восстановления и изоляции прошёл.
- Миграция PostgreSQL 16 применена; у `smetra.file_versions` включены RLS и FORCE RLS, а доступ `anon`/`authenticated` отозван. Весь локальный набор: 146 тестов (1 пропущен), Ruff, web build. Production deployment `dpl_8ssxxPGcHRdEA3tRoRjp64dF6D4X` готов; `/health`, OAuth providers и обновлённый редактор ответили HTTP 200. Production E2E прошёл регистрацию → создание Markdown → правку → историю → восстановление исходного содержимого → удаление временного аккаунта.
- Ключ RuStore успешно получил краткоживущий токен API, но `GET /public/v1/application` вернул 403. По документации RuStore API публикации требует активную версию приложения; ключ также должен включать разрешения нужных методов и приложения. Публикация APK этим ключом пока не подтверждена.
- Ассистент умеет читать ограниченный фрагмент Markdown с сохранением форматирования и предлагать точечную замену текста. Web показывает прежний и предлагаемый фрагменты до подтверждения; в редакторе можно выделить текст и передать его ассистенту с контекстом файла. Применение проверяет исходный SHA-256, отклоняет устаревшую правку и создаёт версию для восстановления. Локальный тест проверил чтение, отсутствие записи до подтверждения, чужой аккаунт, повторное подтверждение и конфликт правок. Production deployment `dpl_AwDKASiAR47asVKpCmxzuoXNFwTu`: по тексту, выделенному как в редакторе, живая бесплатная модель вернула `replace_markdown_text` как неподтверждённое предложение. Тестовый аккаунт удалён. Первый общий запрос без дословного выделения не дал предложения, поэтому результат зависит от точности запроса и доступности модели.

## Реализовано и проверено

Обновление после единого прохода:

- Акт по объекту создаётся из записанных фактических объёмов и сохраняется как неизменяемый черновик PDF. Web и Android умеют создать и скачать его.
- Допработы имеют отдельные версии, цену и срок. Клиент согласует, запрашивает изменения или отклоняет их по ссылке. После отправки версия неизменяема, отозванная ссылка перестаёт работать. Согласованная сумма учитывается в проекте.
- Клиентский PDF-отчёт содержит фактические работы, ход закупок, платежи и фотографии журнала. Закупочные цены и поставщики клиенту не раскрываются.
- Для прикреплённого фото чека web и Android могут запросить OCR и заполнить несохранённый черновик закупки: магазин, дату и сумму. Пользователь проверяет поля и сам сохраняет запись. Запрос ограничен 3 разами в месяц на бесплатном тарифе и 30 на Про. Изоляция файла, лимит и отсутствие автоматической записи проверены тестом. Live-проверка бесплатной vision-модели вернула 429/502; надёжность OCR пока не подтверждена.
- MyTracker SDK 3.6.0 включён в подписанный Android APK: регистрация, вход, создание и отправка сметы, клиент, проект, запись оплаты и AI Capture. Четыре проверки интеграции и Android lint/release build прошли. Серверный S2S-сигнал подтверждённой оплаты подготовлен, но для его отправки нужны отдельные `MYTRACKER_S2S_APP_ID` и `MYTRACKER_S2S_KEY`; предоставленный SDK key их не заменяет.
- В сводке «согласовано за месяц» дата и начало месяца теперь считаются в `Europe/Moscow`. Это исправляет переход между сентябрём и октябрём, когда UTC ещё показывает предыдущий день; добавлен детерминированный тест границы. Из чистого Git checkout прошли 146 тестов (1 пропущен), Ruff, web build и подписанный Android release build. Production deployment `dpl_EVAcY5sUSUYLM4MzFsev9W1Ep3mt`: тестовая смета была согласована и попала в октябрьскую сводку; временный аккаунт удалён.
- PostgreSQL миграция 15 применена с RLS и FORCE RLS. Production deployment `dpl_9Kfmn44c9J7Nh8MJXqa5emRMbej9` проверен smoke-тестом: согласование, сумма, PDF, публичная страница, изоляция аккаунтов. OCR-маршрут больше не даёт 500 при проверке счётчика; бесплатный провайдер ответил 502, закупка осталась неизменной. Временные аккаунты удалены. Локально прошли 145 тестов (1 пропущен), web build собрал 57 файлов, Android lint/release build и проверка подписи APK прошли. APK в RuStore не загружен.

- Строительный режим: объект, помещения, ручные замеры, безопасные формулы объёмов, работы и материалы, расход и запас, коэффициент цены/наценка/скидка, план/факт, XLSX, смета, привязка к согласованному заказу. Фото и документы прикрепляются к объекту.
- Дефектная ведомость: помещение, описание, замер, предлагаемая работа, важность, статусы и фото. Web и нативный Android используют один API. PostgreSQL изолирует записи по рабочему пространству через RLS.
- Журнал работ: дата, исполнители, число людей, выполненная работа и объём, комментарий, до четырёх фото. Запись по позиции ведёт фактический объём; исправление или удаление записи пересчитывает факт. Сценарий есть в web и нативном Android. Миграция PostgreSQL 12 применена с принудительным RLS; production API smoke проверил создание, фото, правку, изоляцию и удаление.
- Закупки: лёгкий справочник поставщиков, список материалов из ведомости, статус «заказано/получено», количество и цена, приватный чек или накладная. По каждому материалу видны потребность, получение, остаток к покупке и недостача относительно фактического расхода. Web и Android используют общий API. Миграция PostgreSQL 13 применена с принудительным RLS; production smoke проверил поставщика, чек, сумму, права и удаление.
- Внутренние Markdown-заметки: создание у заказа или строительного объекта, предпросмотр, правка с проверкой версии, поиск по извлечённому тексту и чтение ассистентом.
- Ассистент: потоковый чат, история и ветвление диалогов, вложения PDF/TXT/MD прямо в чате, подтверждение предлагаемых действий, инструменты чтения рабочих записей и строительных замеров. Лимит базового доступа — 3 сообщения в месяц; лимит Про — 100. Платёжные и рабочие данные остаются в PostgreSQL.
- Local verification: 145 tests passed (1 skipped); web build contains 57 files. Earlier smoke covered Markdown, defects, daily logs, procurement, file access and QA account cleanup. PostgreSQL schema 15 is current.
- Подписанный `dist/smetra-mobile-1.6.1-release.apk`: `ru.smetra.mobile`, versionCode 11. `lintRelease`, `assembleRelease`, пакет и сертификат проверены. Новая сборка в RuStore не загружалась.

## Не считать выполненным без дальнейшей работы

- Remaining construction work: verify receipt OCR against real receipts and Android UI, then decide whether to add a separately persisted expense draft. The current OCR only prefills an unsaved purchase form; live free vision returned 429/502 during verification.
- Третья очередь: точные AR-замеры, официальные нормативы и индексы, КС-2/КС-3. Не показывать эти функции как готовые без корректных источников и проверки.
- Remaining advanced AI work: background tasks, image search and broader assistant-led bulk edits with reviewable diff/undo. File versioning is limited to the latest 10 Markdown revisions. Current assistant write tools require user confirmation.
- Для расценок ещё не добавлен общий для всех устройств список недавно использованных позиций. Предупреждение о похожей позиции работает при ручном создании; CSV/Excel-импорт пока не сравнивает строки с существующими позициями. Массовая правка сметы работает в локальном черновике и записывается на сервер только при сохранении всей сметы.
- Нативный Android не проверялся на подключённом устройстве после последнего изменения. Нужен инструментальный проход, включая выбор/отмену фото, слабую сеть и восстановление экрана.
- Внешние реальные сценарии оплаты, OAuth-провайдеров и публикации нового APK проверяются отдельно на соответствующих аккаунтах и в RuStore. Локальная сборка и API smoke не подтверждают их.

Нельзя маркировать все предыдущие ТЗ как `PASS`, пока эти пункты не закрыты и не проверены.
