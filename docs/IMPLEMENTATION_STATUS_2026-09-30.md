# Сметра: проверенное состояние на 30 сентября 2026

Это технический журнал проверок, а не заявление о полном завершении всех ТЗ.

## Реализовано и проверено

Обновление после единого прохода:

- Акт по объекту создаётся из записанных фактических объёмов и сохраняется как неизменяемый черновик PDF. Web и Android умеют создать и скачать его.
- Допработы имеют отдельные версии, цену и срок. Клиент согласует, запрашивает изменения или отклоняет их по ссылке. После отправки версия неизменяема, отозванная ссылка перестаёт работать. Согласованная сумма учитывается в проекте.
- Клиентский PDF-отчёт содержит фактические работы, ход закупок, платежи и фотографии журнала. Закупочные цены и поставщики клиенту не раскрываются.
- Для прикреплённого фото чека web и Android могут запросить OCR и заполнить несохранённый черновик закупки: магазин, дату и сумму. Пользователь проверяет поля и сам сохраняет запись. Запрос ограничен 3 разами в месяц на бесплатном тарифе и 30 на Про. Изоляция файла, лимит и отсутствие автоматической записи проверены тестом. Live-проверка бесплатной vision-модели вернула 429/502; надёжность OCR пока не подтверждена.
- PostgreSQL миграция 15 применена с RLS и FORCE RLS. Production deployment `dpl_9Kfmn44c9J7Nh8MJXqa5emRMbej9` проверен smoke-тестом: согласование, сумма, PDF, публичная страница, изоляция аккаунтов. OCR-маршрут больше не даёт 500 при проверке счётчика; бесплатный провайдер ответил 502, закупка осталась неизменной. Временные аккаунты удалены. Локально прошли 145 тестов (1 пропущен), web build собрал 57 файлов, Android lint/release build и проверка подписи APK прошли. APK в RuStore не загружен.

- Строительный режим: объект, помещения, ручные замеры, безопасные формулы объёмов, работы и материалы, расход и запас, коэффициент цены/наценка/скидка, план/факт, XLSX, смета, привязка к согласованному заказу. Фото и документы прикрепляются к объекту.
- Дефектная ведомость: помещение, описание, замер, предлагаемая работа, важность, статусы и фото. Web и нативный Android используют один API. PostgreSQL изолирует записи по рабочему пространству через RLS.
- Журнал работ: дата, исполнители, число людей, выполненная работа и объём, комментарий, до четырёх фото. Запись по позиции ведёт фактический объём; исправление или удаление записи пересчитывает факт. Сценарий есть в web и нативном Android. Миграция PostgreSQL 12 применена с принудительным RLS; production API smoke проверил создание, фото, правку, изоляцию и удаление.
- Закупки: лёгкий справочник поставщиков, список материалов из ведомости, статус «заказано/получено», количество и цена, приватный чек или накладная. По каждому материалу видны потребность, получение, остаток к покупке и недостача относительно фактического расхода. Web и Android используют общий API. Миграция PostgreSQL 13 применена с принудительным RLS; production smoke проверил поставщика, чек, сумму, права и удаление.
- Внутренние Markdown-заметки: создание у заказа или строительного объекта, предпросмотр, правка с проверкой версии, поиск по извлечённому тексту и чтение ассистентом.
- Ассистент: потоковый чат, история и ветвление диалогов, вложения PDF/TXT/MD прямо в чате, подтверждение предлагаемых действий, инструменты чтения рабочих записей и строительных замеров. Лимит базового доступа — 3 сообщения в месяц; лимит Про — 100. Платёжные и рабочие данные остаются в PostgreSQL.
- Local verification: 145 tests passed (1 skipped); web build contains 57 files. Earlier smoke covered Markdown, defects, daily logs, procurement, file access and QA account cleanup. PostgreSQL schema 15 is current.
- Подписанный `dist/smetra-mobile-1.6.1-release.apk`: `ru.smetra.mobile`, versionCode 11. `lintRelease`, `assembleRelease`, пакет и сертификат проверены. Новая сборка в RuStore не загружалась.

## Не считать выполненным без дальнейшей работы

- Remaining construction work: verify receipt OCR against real receipts and Android UI, then decide whether to add a separately persisted expense draft. The current OCR only prefills an unsaved purchase form; live free vision returned 429/502 during verification.
- Третья очередь: точные AR-замеры, официальные нормативы и индексы, КС-2/КС-3. Не показывать эти функции как готовые без корректных источников и проверки.
- Remaining advanced AI work: background tasks, robust file versioning, image search and bulk edits with reviewable diff/undo. Current assistant write tools require user confirmation.
- Нативный Android не проверялся на подключённом устройстве после последнего изменения. Нужен инструментальный проход, включая выбор/отмену фото, слабую сеть и восстановление экрана.
- Внешние реальные сценарии оплаты, OAuth-провайдеров и публикации нового APK проверяются отдельно на соответствующих аккаунтах и в RuStore. Локальная сборка и API smoke не подтверждают их.

Нельзя маркировать все предыдущие ТЗ как `PASS`, пока эти пункты не закрыты и не проверены.
