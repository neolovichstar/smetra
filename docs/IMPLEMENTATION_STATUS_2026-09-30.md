# Сметра: проверенное состояние на 30 сентября 2026

Это технический журнал проверок, а не заявление о полном завершении всех ТЗ.

## Реализовано и проверено

Обновление после единого прохода:

- Акт по объекту создаётся из записанных фактических объёмов и сохраняется как неизменяемый черновик PDF. Web и Android умеют создать и скачать его.
- Допработы имеют отдельные версии, цену и срок. Клиент согласует, запрашивает изменения или отклоняет их по ссылке. После отправки версия неизменяема, отозванная ссылка перестаёт работать. Согласованная сумма учитывается в проекте.
- Клиентский PDF-отчёт содержит фактические работы, ход закупок, платежи и фотографии журнала. Закупочные цены и поставщики клиенту не раскрываются.
- PostgreSQL миграция 14 применена с RLS и FORCE RLS. Production deployment `dpl_6V5Xd6BcoZUdUW3oub83dEC7qteN` проверен smoke-тестом: согласование, сумма, PDF, публичная страница, изоляция аккаунтов. Временные аккаунты удалены. Локально прошёл 141 тест (1 пропущен), web build собрал 57 файлов, Android lint/release build и проверка подписи APK прошли. APK в RuStore не загружен.

- Строительный режим: объект, помещения, ручные замеры, безопасные формулы объёмов, работы и материалы, расход и запас, коэффициент цены/наценка/скидка, план/факт, XLSX, смета, привязка к согласованному заказу. Фото и документы прикрепляются к объекту.
- Дефектная ведомость: помещение, описание, замер, предлагаемая работа, важность, статусы и фото. Web и нативный Android используют один API. PostgreSQL изолирует записи по рабочему пространству через RLS.
- Журнал работ: дата, исполнители, число людей, выполненная работа и объём, комментарий, до четырёх фото. Запись по позиции ведёт фактический объём; исправление или удаление записи пересчитывает факт. Сценарий есть в web и нативном Android. Миграция PostgreSQL 12 применена с принудительным RLS; production API smoke проверил создание, фото, правку, изоляцию и удаление.
- Закупки: лёгкий справочник поставщиков, список материалов из ведомости, статус «заказано/получено», количество и цена, приватный чек или накладная. По каждому материалу видны потребность, получение, остаток к покупке и недостача относительно фактического расхода. Web и Android используют общий API. Миграция PostgreSQL 13 применена с принудительным RLS; production smoke проверил поставщика, чек, сумму, права и удаление.
- Внутренние Markdown-заметки: создание у заказа или строительного объекта, предпросмотр, правка с проверкой версии, поиск по извлечённому тексту и чтение ассистентом.
- Ассистент: потоковый чат, история и ветвление диалогов, вложения PDF/TXT/MD прямо в чате, подтверждение предлагаемых действий, инструменты чтения рабочих записей и строительных замеров. Лимит базового доступа — 3 сообщения в месяц; лимит Про — 100. Платёжные и рабочие данные остаются в PostgreSQL.
- 141 локальных тестов прошли (1 пропущен без отдельной PostgreSQL test DB), web build собрал 57 файла. Production smoke проверил Markdown, дефекты, журнал работ, закупки, фото, загрузку файла из чата, права на файл и удаление временных аккаунтов. Миграция PostgreSQL 13 применена, RLS и policy для новых таблиц проверены.
