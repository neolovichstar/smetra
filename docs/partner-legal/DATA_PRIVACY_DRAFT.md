# Приложение по данным, приватности и информационной безопасности (проект)

**НЕ публичная политика и НЕ подписанное поручение по обработке ПДн. Требует проверки фактических потоков данных, места хранения и сторон договора. Редакция 2026-10-26.**

## Предмет обработки и минимизация
Сервис собирает по переходу по партнёрской ссылке случайный идентификатор клика в HttpOnly-cookie; после регистрации связывает идентификатор с внутренним аккаунтом. Возникает профиль использования, потенциально относящийся к ПДн, даже без передачи email магазину. Подписки подтверждаются платёжной системой, а не партнёрскими отчётами. Партнёру выдаются только ограниченные агрегаты: количество переходов, регистраций, успешных оплат, суммы комиссий и обезличенные квитанции. Партнёру не передаются пользовательские email, телефоны, IP, сметы, сведения о клиентах или платёжные реквизиты.

События магазина передаются через серверный API с уникальным event_key без персональных данных. Не допускаются произвольные метаданные, номер телефона, email, адрес, IP или сырой идентификатор покупателя. События магазина имеют отметку `trusted:false`, не влияют на подтверждённые комиссии.

## Роли и основания
До подписания определить для каждой обработки: (а) оператора данных; (б) лицо, действующее по поручению; (в) отдельного самостоятельного оператора; (г) основание по ст. 6 ФЗ №152-ФЗ и необходимость согласия. Не считать маркетинговую аналитику автоматически «обязательной» для выполнения пользовательского договора. Получать надлежащее согласие там, где оно требуется; реализовать процедуры отзыва и прекращения обработки, не нарушая обязательного хранения финансовых документов.

## Матрица данных
| Категория | Цель | Доступ | Текущая техническая политика / проверка |
|---|---|---|---|
| Партнёрский клик (хэш случайного токена) | первичная атрибуция | только backend | cookie до 30 дней; неатрибутированные клики очищаются после срока действия + 14 дней. При наличии связи с комиссией технический хэш события сохраняется для учётного следа до законного удаления/анонимизации |
| Профиль атрибуции (внутренний user_id) | один партнёр / новый клиент | только backend | на период определения обязательств и установленного срока хранения; отдельно оценить срок |
| Факт оплаты (платёж, сумма) | проверка комиссии | backend | по правилам учёта и законных требований, не удалять произвольно |
| Комиссионная квитанция | сверка | партнёр (без customer ID) | статус held, cleared_unpaid, reversed; платежи не отправляются |
| Click-out магазина | статистика | агрегаты партнёра | raw события очищаются после 180 дней |
| События магазина | аналитика (self-reported) | агрегаты партнёра | raw события очищаются после 180 дней |
| API-ключи | защищённый доступ | хэш в backend | отозвать, ротировать при утечке |
| Сессии консоли | авторизация | хэш в backend | 1 час + удаление после grace |
| DNS/meta подтверждение | защита товаров | backend и сам партнёр | перепроверка права на домен через 90 дней |

Строки в таблице описывают техническую модель — не безусловное юридическое основание хранения.

## Меры защиты
TLS, segregated API principal, уникальные секреты, хэширование ключей, rate limit, проверка доменов, запрет SSRF/открытых редиректов, запрет небезопасных URL, RLS/REVOCATION на базе и обязательное тестирование изоляции партнёров. Настройка резервного копирования и восстановления, журнал доступа к чувствительным операциям, минимум прав для инфраструктурных токенов, ревизия сторонних SDK. Не хранить секреты в git, браузере, аналитических событиях и request logs.

## Поставщики, локализация и трансграничность
Подтвердить физические регионы размещения, правовые основания взаимодействия и субподрядчиков Vercel, Supabase, Cloudflare, YooKassa, MyTracker, OpenRouter и иных сервисов. Для граждан РФ проверить требования о локализации при первичном сборе по ст. 18 ч. 5 и уведомление о трансграничной передаче по ст. 12. Нельзя заявлять, что локализация соблюдена, лишь потому что база находится в регионе ЕС. До согласования удалить любые публичные утверждения о полном соответствии законодательству.

## Права субъектов
Определить и документировать: доступ, исправление, отзыв согласия, удаление/блокировка, сроки ответа, ограничения для финансового учёта и анонимизацию статистики. Обращения support@smetra.online; безопасность abuse@smetra.online. Удаление аккаунта не должно обнажать бухгалтерские записи другого лица.

## Инциденты
При подозрении на утечку немедленно изолировать ключи, ограничить доступ, сохранить необходимые журналы, оценить правовые последствия. По ст. 21 ч. 3.1 ФЗ 152-ФЗ для подходящих инцидентов указаны уведомление уполномоченного органа в 24 часа и результаты внутреннего расследования в 72 часа. Решение о применимости и отправку оформляет назначенный ответственный и юрист. Запись инцидента не должна включать секретные токены.

## Контроль исполнения перед запуском
Провести DPIA/оценку ПДн, data mapping, аудит статусов ОРД/ЕРИР, тесты BOLA/IDOR и подтверждения оплаты, проверку RLS и реализации прав субъектов. Подписать поручение/соглашение о данных, если оно действительно необходимо по характеру отношений.
