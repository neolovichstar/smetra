# Автоматические зашифрованные копии PostgreSQL

## Текущее состояние

Сценарий находится в `.github/workflows/postgres-backup.yml`. По расписанию он должен запускаться ежедневно в **04:37 UTC**, но GitHub запускает `schedule` **только из основной ветки репозитория**. Сейчас `main` отстаёт от версии, развёрнутой на Vercel: без проверки настроек автоматической публикации не переносить устаревший код в продакшен.

**Работающие тесты резервного копирования не означают, что пользовательские данные уже копируются.** Пока не настроены защищённые параметры и не прошёл реальный запуск GitHub Actions, автоматические копии продакшен-базы не подтверждены.

Срок хранения артефактов GitHub Actions — **30 дней**. Это временный вариант, а не полноценная система долговременного восстановления.

## Однократная настройка у владельца

1. Установить утилиту [age](https://github.com/FiloSottile/age/releases) **на свой доверенный компьютер** и создать ключ:

   ```sh
   age-keygen -o smetra-backup-identity.txt
   age-keygen -y smetra-backup-identity.txt
   ```

   Приватный файл `smetra-backup-identity.txt` сохранить минимум в двух защищённых местах, доступных только владельцу. **Нельзя отправлять его в GitHub, чат, Vercel, Supabase или Upstash.** Потеря ключа означает невозможность расшифровать архивы.

2. Открыть GitHub → репозиторий `neolovichstar/smetra` → Settings → Secrets and variables → Actions. Создать **Variable** `SMETRA_BACKUP_AGE_RECIPIENT` со значением публичного ключа (начинается с `age1`), полученного второй командой.

3. Там же создать **Repository secret** `SMETRA_BACKUP_DATABASE_URL`. Точный URL брать из Supabase → Connect, режим **Session pooler**, порт **5432**, добавить `sslmode=require`. Не выдумывать hostname. Прямое подключение Supabase Free может требовать IPv6 и не работать на сервере GitHub. **Transaction pooler (6543) нельзя использовать** для `pg_export_snapshot` + `pg_dump`. Учётная запись должна иметь права читать все данные приватной схемы `smetra`. Никогда не добавлять этот URL в исходники или настройки браузера.

4. После проверки параметров деплоя Vercel безопасно перенести сценарий и инструмент резервного копирования в **основную ветку GitHub**. Не обновлять слепо устаревшую ветку `main`, иначе можно случайно опубликовать старую версию приложения.

5. Выполнить GitHub → Actions → Encrypted PostgreSQL backup → Run workflow. Убедиться, что архив содержит **только** `*.tar.age` и `*.sha256`, затем проверить восстановление. Включить уведомления GitHub о сбоях Actions.

## Проверка восстановления

Скачать зашифрованный артефакт и на своём компьютере с приватным ключом выполнить:

```sh
sha256sum -c smetra-DATE-runID.tar.age.sha256
mkdir -m 700 /private/smetra-restore
age -d -i /secure/smetra-backup-identity.txt -o /private/smetra-restore/backup.tar smetra-DATE-runID.tar.age
tar -tf /private/smetra-restore/backup.tar
tar -xf /private/smetra-restore/backup.tar -C /private/smetra-restore
```

Создать **новую пустую PostgreSQL 17 на локальном компьютере** с БД `smetra_restore_...` и нужными ролями/платформенными схемами. Затем вызвать `python -m backend.manage restore-check --archive ПУТЬ_К_ДАМПУ`, задав `RESTORE_DATABASE_URL` на эту локальную базу. Инструмент сравнит содержимое, индексы, ограничения, разрешения и RLS. В рабочую БД восстанавливать запрещено.

## Ограничения

- Копия **только** схемы `smetra` не содержит объекты Supabase Storage, внешние файлы, данные Auth из других схем и настройки провайдеров. Их нужно архивировать отдельно.
- Запуски `schedule` могут задерживаться и пропускаться. Отслеживать возраст **последнего успешно созданного архива**, а не только дату последнего запуска.
- GitHub не является независимым долговременным хранилищем. В перспективе необходимо отдельное приватное хранилище с шифрованием, версионированием и контролем сохранности.
- На GitHub runner передаётся **только публичный** ключ `age`. Приватный ключ туда никогда не загружать.
- Перед восстановлением реальных данных остановить обработчики платежей/уведомлений и сверить историю с ЮKassa, чтобы исключить дублирование операций.
