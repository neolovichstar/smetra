# Публикации «Что нового»

Этот документ — постоянное правило сопровождения проекта «сметра.». Обновляйте его вместе с выпуском изменений.

- `apps/web/whats-new.json` — источник публикаций. Новые посты сверху; уникальный `id` не изменять после выпуска. Дата — `YYYY-MM-DD`.
- Для крупного релиза: `status: "released"`, `type: "major"`, содержательный заголовок, короткое резюме и список ощутимых пользовательских изменений.
- Для исправлений без изменения пользовательского сценария: `status: "released"`, `type: "patch"`. Пишите коротко, объединяйте связанные мелкие фиксы, не создавайте пост на каждый коммит.
- Для дорожной карты: `status: "development"`, `type: "preview"`. Не описывать планы как выпущенные функции. При выпуске создать *новый* пост с новым идентификатором.
- Использовать только разрешённые SVG-иконки из локального реестра `iconPaths` в `apps/web/whats-new.js`. Для каждого изменения допустимо `{"icon":"ruler","text":"..."}`; SVG HTML из JSON никогда не вставлять. Не использовать эмодзи.
- Публикация выпускается **в том же релизе**, что и соответствующий функционал, после проверки реального поведения. Не делать пост о внедрённом функционале, пока изменения только в черновом PR.
- Использовать нейтральную чёрно-серую палитру. Следить за экраном телефона, доступностью и отсутствием горизонтальной прокрутки.
- После правок проверять валидность JSON, JS, статическую отдачу файла, отсутствие XSS и то, что индикатор непрочитанного не срабатывает для `development`.

Пример короткого патча:

```json
{
  "id": "patch-example-YYYY-MM-DD",
  "date": "YYYY-MM-DD",
  "status": "released",
  "type": "patch",
  "icon": "bug",
  "title": "Исправления интерфейса",
  "summary": "Убраны визуальные ошибки.",
  "changes": [
    {"icon": "check", "text": "Исправлены отступы и состояния кнопок."}
  ]
}
```
