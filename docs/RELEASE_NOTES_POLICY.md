# Публикация обновлений «сметра.»

Стандарт для каждого пользовательского релиза. Применять при выпуске изменений, а не при создании черновой ветки.

## Крупное обновление
- Полноценный пост в существующем **серверном** разделе «Что нового», через административный интерфейс или `POST /api/changelog` с авторизованной административной сессией.
- Заголовок отражает пользовательскую ценность, версия/дата относятся к реально выложенной сборке, внутри — только проверенные возможности и ограничения.
- В заголовке и подзаголовках/списках интерфейс выводит подходящие монохромные SVG-иконки из **локального реестра** `releasePaths` в `apps/web/workspace-vault.js`. Эмодзи не используются; пользовательский Markdown не содержит необработанный SVG.
- Персональная метка непрочитанного, просмотры и реакции обслуживаются существующим backend `backend/changelog.py`, не заменять их локальным хранилищем.

## Патч
- Небольшие багфиксы группировать в краткую публикацию с названием `Патч: ...`, 1–4 конкретных пункта.
- Технические изменения без влияния на пользователя можно не публиковать по одному коммиту.

## Правила безопасности релиза
- Не описывать функцию как выпущенную, пока код не прошёл проверки и не вышел в production; APK-функции объявлять только после доставки нужной Android-версии.
- Не публиковать OAuth-токены, приватные ссылки, секреты или данные пользователей.
- Прежде чем выпускать: python/Node JS проверки, проверка экрана телефона, повторная проверка доступов и сброса сессий.
- При ошибке публикации не пытаться создать дубликаты: сверить записи по названию и версии.
- Не отправлять "вышло обновление" по одному факту успешного git commit или draft pull request.

Пример для крупного релиза:

```md
# ИИ для строительных задач
## Работа с аудиозаписями
- Добавлены прикрепление и расшифровка; размеры из речи требуют проверки.
## Дизайн-проекты
- Доступен разбор планировки и страниц PDF с указанием ограничений.
```

Пример короткого патча:

```md
# Патч: исправления авторизации
- Корректный возврат в Android после успешного входа.
- Проверка сессии перед открытием рабочего кабинета.
```
