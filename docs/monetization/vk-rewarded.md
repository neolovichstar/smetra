# Видео с вознаграждением: VK Ad SDK

Android 2.2.0 (46) использует прямой `com.my.target:mytarget-sdk:5.52.5` (VK Ad SDK, прежнее название — myTarget). Yandex Mobile Ads удалён из приложения; кабинет и договор РСЯ для этой интеграции не нужны. Вход через Яндекс ID и Яндекс Диск продолжают работать независимо от рекламной сети.

## Подключение для самозанятого в РФ

По [официальной справке VK](https://ads.vk.ru/help/partner/partner_start/partner_self_employed), проверенной 10 ноября 2026 года:

1. Создайте **кабинет партнёра Рекламной сети VK**, тип «физическое лицо». Это кабинет монетизации приложения, а не кабинет покупки рекламы.
2. Подключите верифицированный VK ID. В настройках выберите «Подключить самозанятость», пройдите проверку и предоставьте сервису VK Реклама права в «Моём налоге».
3. В разделе «Финансы» выберите банк. Выплаты осуществляются в рублях через СБП на телефон из VK ID, минимум 5 000 ₽, не чаще раза в месяц. Условия оферты и проверка данных обязательны. По справке VK, сведения для чеков передаются автоматически, налог самозанятый оплачивает самостоятельно.
4. [Добавьте Android-приложение](https://ads.vk.ru/help/partner/partner_app/partner_create_app): пакет `ru.smetra.mobile`, ссылка на реальную страницу «Сметры» в RuStore. Пройдите модерацию.
5. Создайте рекламный блок **«Видео с вознаграждением»**. Скопируйте его числовой **slot ID**, не ID кабинета, приложения или баннерного блока.
6. В серверных переменных production-проекта «Сметры» на Vercel установите `VK_REWARDED_SLOT_ID=<ваш slot ID>` и разверните сервер. Пароли VK и банковские реквизиты в приложение или репозиторий не добавляются.
7. Установите подписанный APK 2.2.0 (46). Проверьте реальный показ на бесплатном аккаунте с исчерпанными токенами: досмотр → 45 000 токенов, раннее закрытие → без начисления, повторный запрос → без второй награды.

Нужен только один рекламный slot ID на сервере: повторно собирать APK для смены блока не требуется. Старое `YANDEX_REWARDED_AD_UNIT_ID` больше ничего не включает. Без корректного `VK_REWARDED_SLOT_ID` предложение просмотра скрыто, новые попытки запрещены; уже заработанная и сохранённая на устройстве награда может быть восстановлена в пределах срока попытки.

## Поведение и ограничения

- Только добровольное видео после нажатия пользователем. Гостям реклама не даёт серверных токенов. На платных тарифах предложение отключено. Баннеров, фоновых запросов объявления и автоматических полноэкранных показов нет.
- Награда прежняя: **45 000 токенов**, максимум одно начисление на аккаунт за календарный день по Москве. Это токены внутреннего кошелька, не обещание ровно трёх ответов: расход зависит от модели и документов. Тарифные лимиты не изменены.
- Сервер выдаёт ограниченную по времени попытку с хешем nonce в базе. Начисление выполняется транзакционно с блокировкой пользователя и уникальной дневной записью, повтор одного завершённого запроса идемпотентен.
- Приложение запрашивает начисление после `RewardedAdListener.onReward`. До сетевого запроса оно сохраняет nonce в закрытом хранилище, привязанном к владельцу; токен авторизации там не сохраняется. Временная ошибка сети не требует повторного видео. При следующем входе начисление повторяется, пока попытка не истекла (24 часа). Очистка данных приложения удаляет локальную запись.
- Это **клиентское подтверждение SDK**, не независимая серверная квитанция рекламной сети. Модифицированный клиент может подделать факт досмотра; сервер ограничивает ущерб дневным лимитом. Не используйте эту схему для денежных или обмениваемых на деньги наград. Подписанное серверное подтверждение нельзя изображать реализованным без документированного протокола поставщика.
- Содержимое смет, переписка, имя, email, VK ID, координаты и идентификатор аккаунта не добавляются в рекламный запрос приложением. `MyTargetPrivacy.setUserConsent(false)` отключает согласие на персонализированную рекламу; SDK всё равно обрабатывает технические данные, необходимые для объявления, по своим условиям. Запрос разрешения на геолокацию не добавлен.
- Старые APK с Яндекс SDK при попытке запуска получают понятный ответ о необходимости обновления (HTTP 426), а не slot ID другой сети. Обычная работа смет, входа и чатов остаётся совместимой.

## Тестирование рекламы

[Официальный тестовый режим VK](https://ads.vk.ru/help/partner/partner_integration/partner_android/partner_android_test) использует instance ID тестового устройства и `MyTargetConfig.Builder.withTestDevices(...)`. Не включайте тестовые устройства в production-сборке и не нажимайте на реальные объявления при проверках. В репозитории нет выдуманного demo slot ID и нет автоматической выдачи награды за тестовую кнопку.

Локальная фикстура может подготовить отдельный бесплатный аккаунт с исчерпанным лимитом при `SMETRA_NATIVE_REWARDED_TEST=1`; реальный тестовый блок задаётся через `SMETRA_NATIVE_REWARDED_SLOT_ID`. База фикстуры одноразовая, сервер доступен только через loopback. Результаты API-тестов не подтверждают коммерческий показ или выплату: для этого нужны ваш допущенный блок, устройство и кабинет VK.

Источники SDK: [официальный репозиторий и актуальная зависимость](https://github.com/myTargetSDK/mytarget-android), [RewardedAd](https://ads.vk.ru/help/partner/partner_integration/partner_android/partner_android_rewarded).
