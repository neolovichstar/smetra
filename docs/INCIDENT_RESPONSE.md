# Реагирование на инциденты «сметра.»

Канал владельца: `reyzin378@gmail.com`. В журнале инцидента фиксировать время UTC, затронутые сервисы, идентификаторы запросов и решения; не записывать токены, пароли, тела заявок и клиентские файлы.

1. **Сдержать.** Для утечки ключа отключить/перевыпустить ключ у провайдера и обновить серверную переменную окружения. Для злоупотребления API включить временные правила Vercel Firewall, ограничить конкретный маршрут. Для платежей временно выключить checkout через `YOOKASSA_MODE=off`, сохранив доступ к уже оплаченным данным. Записать время и значение изменённого флага без секрета.
2. **Оценить масштаб.** По request ID, audit/event журналам и панели провайдера определить пользователей, интервал и тип данных. При подозрении на доступ к БД проверить роли/гранты, журнал запросов и экспорты. Не считать отсутствие ошибок доказательством отсутствия доступа.
3. **Устранить.** Исправить первопричину в коде/конфигурации, добавить тест на воспроизведение, проверить на изолированном окружении. После компрометации сессий удалить активные сессии затронутых пользователей; после раскрытия OAuth/YooKassa/OpenRouter ключей заменить их у источника, а не только в Vercel.
4. **Восстановить и наблюдать.** Развернуть проверенную сборку, сверить оплаты с YooKassa, проверить целостность данных и сохранность backup. Наблюдать ошибки, 401/403/429, webhooks и траты AI. Зафиксировать дату следующей проверки.
5. **Сообщить.** Владелец определяет необходимость уведомления клиентов и регуляторов по фактическим данным инцидента и применимому праву. Публичное сообщение не должно раскрывать чужие PII или служебные секреты.

## Перевыпуск ранее раскрытых секретов

Владелец должен перевыпустить токены Vercel, GitHub, OpenRouter, бота и пароль PostgreSQL, ранее отправленные в чат, а также YooKassa secret key. По каждому ключу: создать новый у провайдера → сохранить в Vercel Environment Variables/локальном игнорируемом файле → проверить сервис → отозвать старый → проверить, что старый не действует. Не коммитить ключи и не присылать их в чат. После замены пароля БД проверить все deployment environments и резервные задания. Статус замены пока **NOT VERIFIED**.

## Backup drill

Восстановление выполнять в отдельную БД и схему, затем сверить число таблиц, миграции, ограничения, роли/RLS и небольшой набор обезличенных данных. Нельзя восстанавливать тестовую копию поверх production. Зафиксировать RPO/RTO по фактическому времени. Drill пока **NOT VERIFIED**.
