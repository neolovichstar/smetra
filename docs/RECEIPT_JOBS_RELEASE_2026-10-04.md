# Фоновое распознавание чеков · 1.7.8

Фото чека обрабатывается в очереди, а результат сохраняется в приватном черновике.
Можно уйти с экрана и вернуться к закупке. Сумма, магазин и дата переносятся
в форму только отдельным действием; закупка сохраняется обычной кнопкой после проверки.
Существующее примечание сохраняется. Итог всего чека явно отделён от цены материала.

- Backend: короткая операция постановки в очередь, вызов модели без блокировки
  записи базы; повторная проверка сессии, роли, исходного фото и lease перед сохранением.
- Повтор одного ключа возвращает исходную задачу, даже после отмены и новой попытки.
  Повторное распознавание уже готового фото использует сохранённый результат.
- Отдельная общая для устройств квота OCR: 3 в месяц бесплатно, 30 при действующем
  «Про». Чатовая квота не расходуется. Ошибка и отмена возвращают резерв один раз.
- Не более двух активных чеков пользователя в рабочем пространстве; до трёх
  попыток при временной ошибке провайдера. Платные модели запрещены.
- Сайт: компактный блок в форме закупки, статус, отмена, повтор, явный перенос.
  APK: нативный блок на странице закупки и подтверждение перехода в форму.
- PostgreSQL migration 25 расширяет существующую закрытую очередь. Права публичных
  ролей не расширялись; доступ остаётся через проверенную сессию и RLS.

Проверено: backend regression suite; отдельные проверки параллельного повтора,
квоты, отмены в ходе генерации, отзыва сессии, смены фото, потери lease, некорректной
суммы и сохранности закупки (11 отдельных тестов очереди чеков). Браузерный сценарий на 390 px и нативный сценарий
на Android 35 прошли с изолированным API и тестовым ответом модели.
Прямой запрос к живому `openrouter/free` правильно определил итог 123450 копеек
и дату синтетического чека с несколькими позициями. Это не оценка точности
на настоящих российских кассовых чеках; её ещё нужно провести.
Реальная production-цепочка Supabase cron → Vercel → бесплатная vision-модель
→ сохранённый черновик тоже прошла: точный итог и дата, одна квота OCR,
нулевая чатовая квота, отсутствие закупок. Проверены API-изоляция и RLS
для второго аккаунта; временные аккаунты и их данные удалены.

Границы: PNG/JPEG до 2 МБ; сканы PDF пока требуют отдельного OCR-конвейера.
Цена в форме рассчитывается из всего итога чека, поэтому пользователь должен
исправить её для многопозиционного чека. Никаких автоматических платежей
или записей закупок. Старый синхронный endpoint сохранён для совместимости
с предыдущими APK; новый сценарий требует обновления до 1.7.8.
