# Smetra Partner API

**Версия:** v1, пилот · **Базовый адрес:** `https://console.smetra.online/api/partners/v1` · **Для покупателей:** `https://smetra.online`

## Введение

Partner API связывает магазин стройматериалов со «Сметрой»: вы публикуете каталог, размещаете партнёрскую ссылку и видите переходы, регистрации, подтверждённые подписки и клики по товарам.

Все ответы — JSON по HTTPS, денежные значения — целые числа **в копейках**, время — Unix-секунды, группировка по дням — UTC. Ответы не кэшируются.

**Машиночитаемая схема:** [OpenAPI 3.1 JSON](/partner-openapi.json) — для генерации клиентов и контрактных тестов. Старые пути `/api/partners/console/*` временно продолжают работать.

> Выплаты по партнёрской программе отключены до оформления договоров, налоговой модели и расчётных реквизитов. В консоли доступны только начисления для сверки — это не произведённые выплаты.

## Быстрый старт

1. Получите у команды «Сметры» код партнёра и секретный API-ключ. Ключ показывается один раз.
2. Войдите в [кабинет партнёра](/app) этим ключом.
3. Подтвердите домен магазина через **DNS TXT** или **HTML meta-тег**.
4. Разместите партнёрскую ссылку или JavaScript SDK на сайте.
5. Загрузите каталог материалов через серверный API.
6. Смотрите аналитику в кабинете или через Python SDK.

Первый запрос:

~~~bash
curl -s https://console.smetra.online/api/partners/v1/console/profile \
  -H "Authorization: Partner $SMETRA_PARTNER_API_KEY"
~~~

## Авторизация

**Кабинет партнёра.** Сотрудники входят своим аккаунтом «Сметры» — почтой или через Яндекс ID, тем же, что на smetra.online. Доступ к партнёру выдаёт владелец кабинета в разделе «Команда» по почте аккаунта; почта должна быть подтверждена. Роли: владелец, администратор, аналитик (только просмотр) и каталог (товары, домен, события, без денег и статистики). Права проверяет сервер при каждом запросе; удалённый участник теряет доступ сразу.

Технически вход устроен так: smetra.online, где хранится сессия аккаунта, выдаёт одноразовый код на 2 минуты и возвращает человека в кабинет; кабинет обменивает код на сессию на 1 час (`POST /api/partners/v1/console/session/sso`). Сессия аккаунта smetra.online в кабинет не передаётся.

**Серверная интеграция.** Запросы с вашего сервера передают ключ в заголовке:

~~~http
Authorization: Partner smp_live_YOUR_SECRET_KEY
~~~

Кабинет можно открыть и ключом: он обменивается на отдельную сессию сроком 1 час:

~~~http
POST /api/partners/v1/console/session
Content-Type: application/json

{"api_key":"smp_live_YOUR_SECRET_KEY"}
~~~

Ответ `201`: `{"session_token":"smp_session_...","expires_in":3600}`. Последующие запросы:

~~~http
Authorization: PartnerSession smp_session_...
~~~

Сессия истекает сама; `POST /api/partners/v1/console/logout` отзывает её досрочно. Авторизация партнёра полностью отделена от входа пользователей «Сметры».

## API-ключи

- Ключ выдаёт администратор «Сметры» после согласования условий. В базе хранится только SHA-256-хеш.
- **Нельзя** передавать ключ в JavaScript на сайте, в мобильном приложении, в URL или в репозитории. Используйте серверную интеграцию или временную сессию кабинета.
- Замена ключа выполняется администратором по запросу: старый ключ и все сессии кабинета сразу перестают работать.
- Если ключ мог попасть третьим лицам, напишите на [sales@smetra.online](mailto:sales@smetra.online) — ключ заменят.

## Партнёрские ссылки

~~~text
https://smetra.online/api/partners/r/YOUR_PARTNER_CODE
~~~

При переходе сервер создаёт анонимный идентификатор посещения в HttpOnly-cookie и ведёт пользователя к регистрации. Если в течение 7 дней создан **новый** аккаунт, после его первого рабочего запроса атрибуция фиксируется за партнёром (первое касание).

Существующие аккаунты не переназначаются другому партнёру; тестовые платежи не создают комиссий. Искусственный трафик, саморефералы и нарушения правил программы запрещены.

Параметры кампаний и UTM-метки сервер пока не сохраняет: не добавляйте их в ссылку.

## Подтверждение домена

Подтверждение показывает, что партнёр контролирует домен, указанный при подключении. Пока домен не подтверждён, товары можно загружать, но они **не показываются** пользователям, а события магазина не принимаются.

Подтверждение действует **90 дней**, выданный код — **7 дней**.

### Способ 1: DNS TXT

~~~http
POST /api/partners/v1/console/domain
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{"method":"dns"}
~~~

Ответ содержит домен, код и статус. Для магазина `store.example.org` добавьте запись:

~~~text
Type:  TXT
Name:  _smetra-verification.store.example.org
Value: smetra-verify-<выданный код>
~~~

Затем запустите проверку:

~~~http
POST /api/partners/v1/console/domain/verify
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{}
~~~

Проверка читает TXT-запись через фиксированный DNS-over-HTTPS-резолвер. Распространение DNS может занять несколько часов.

### Способ 2: HTML meta-тег

Создайте проверку с `{"method":"meta"}` и разместите тег в `<head>` главной страницы:

~~~html
<meta name="smetra-domain-verification" content="smetra-verify-<выданный код>">
~~~

Затем вызовите тот же `POST /domain/verify`. Нужна HTTPS-страница по **точному домену**, ответ `200` и `text/html`; перенаправления не поддерживаются, читаются первые 64 КБ. Верификатор не обращается к частным IP-адресам.

Текущее состояние: `GET /api/partners/v1/console/domain`. Статусы: `not_started`, `pending`, `verified`, `expired`.

## Каталог

Пакет — до **100 товаров за запрос** и до 64 КБ тела:

~~~http
POST /api/partners/v1/console/catalog
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{
  "products": [
    {
      "sku": "BLOCK-300",
      "name": "Газобетонный блок 600×300×200",
      "price_kopecks": 17900,
      "url": "https://store.example.org/catalog/BLOCK-300",
      "available": true
    }
  ]
}
~~~

Ответ: `{"accepted": 1}`.

| Поле | Правило |
|---|---|
| `sku` | 1–80 символов: латиница, цифры, `_ . : -`; уникален в пакете. Повторная загрузка того же SKU обновляет товар |
| `name` | 1–200 символов |
| `price_kopecks` | Целое число от 0 |
| `url` | HTTPS-ссылка на **подтверждённый домен** партнёра, без порта, логина и пароля |
| `available` | `true` или `false`, по умолчанию `true`. Удаления нет: снимите товар с продажи |

Чтение своего каталога — постранично, курсор берётся только из предыдущего ответа:

~~~http
GET /api/partners/v1/console/products?limit=50&cursor=
~~~

Пользователи «Сметры» видят только товары в наличии у партнёров с действующим подтверждением домена.

Как товары попадают к пользователю. Ассистент «Сметры» предлагает их, когда пользователь собирает закупку по своей смете или спрашивает, где купить материалы. Подбор делает сервер, а не модель: берутся только материалы из сметы или из запроса пользователя (строки работ пропускаются), название товара должно совпадать с материалом. Если подходят товары нескольких партнёров, предложения распределяются между ними, а при равной релевантности порядок меняется каждый день. Купить или поднять позицию в выдаче за плату нельзя. Переход к товару идёт через `https://smetra.online/api/partners/out/{product_id}` и учитывается сервером. Заказ оформляется на сайте магазина.

## Аналитика

~~~http
GET /api/partners/v1/console/summary
GET /api/partners/v1/console/analytics?days=30
~~~

Периоды: `7`, `30`, `90` дней, группировка по UTC.

| Поле | Значение | Достоверность |
|---|---|---|
| `visits` | Переходы по ссылке | Фиксирует сервер |
| `registrations` | Новые атрибутированные аккаунты | Фиксирует сервер |
| `verified_subscription_payments` | Платежи, подтверждённые платёжной системой, без тестовых | Проверено |
| `outbound_material_clicks` | Переходы на товар магазина | Фиксирует сервер |
| `merchant_reported` | События и заказы, отправленные магазином | **Со слов партнёра, не подтверждение оплаты** |
| `timeline` | Показатели по дням | UTC |

Партнёр видит только свои товары, воронку и начисления. Имена, email, IP и действия пользователей не передаются.

## Комиссии

Начисление появляется только после подтверждения платежа за подписку платёжной системой. Повторные уведомления не создают дублей. Полный возврат аннулирует начисление.

Условия по умолчанию: **20% с подтверждённого платежа** в течение **12 месяцев с первой оплаты** пользователя; фактические условия задаются для каждого партнёра. Период ожидания возвратов — 30 дней.

~~~http
GET /api/partners/v1/console/commissions?limit=30&cursor=
~~~

| Статус | Значение |
|---|---|
| `held` | Идёт период ожидания возвратов |
| `cleared_unpaid` | Период прошёл, выплата **не произведена** |
| `reversed` | Начисление аннулировано возвратом |

В журнале только номер квитанции, суммы, ставка и даты — без данных покупателя. API для отправки денег и выплатного кошелька нет.

## События

Ваш сервер может присылать обезличенные события виджета и заказов, чтобы сопоставлять их с переходами:

~~~http
POST /api/partners/v1/console/events
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{
  "event_key": "store-order-2026-000012",
  "event_type": "material_order_reported",
  "amount_kopecks": 259900
}
~~~

Ответ `202`: `{"accepted": true, "trusted": false, "used_for_commissions": false}`.

- Типы: `widget_impression`, `widget_click`, `material_order_reported`.
- `event_key` — стабильный уникальный ключ, 12–100 символов. Повтор с тем же ключом безопасен; тот же ключ с другими данными вернёт `409`.
- Сумма: `0` для событий виджета, положительная — для заказа.
- События принимаются только при подтверждённом домене.
- Ключи хранятся в виде SHA-256. Не используйте в них email, телефоны, адреса и другие персональные данные.

Данные магазина не меняют конверсии подписок и не создают комиссий.

## SDK

### JavaScript для сайта

Публичный SDK без ключей:

~~~html
<div id="smetra-action"></div>
<script src="https://console.smetra.online/partner-sdk.js"></script>
<script>
  SmetraPartner.mount({
    code: "YOUR_PARTNER_CODE",
    container: "#smetra-action",
    label: "Составить смету бесплатно"
  });
</script>
~~~

Для существующих ссылок:

~~~js
SmetraPartner.attach({ code: "YOUR_PARTNER_CODE", selector: "a.smetra-link" });
~~~

SDK не отслеживает посетителей скрытно: учитывается только переход по ссылке.

### Python для сервера

Исходники в репозитории: `sdk/python/`.

~~~bash
pip install -e ./sdk/python
~~~

~~~python
import os
from smetra_partner import PartnerClient

client = PartnerClient(os.environ["SMETRA_PARTNER_API_KEY"])
print(client.analytics(days=30))

client.report_event(
    event_key="order-2026-00000001",
    event_type="material_order_reported",
    amount_kopecks=259900,
)
~~~

Методы: `profile`, `summary`, `analytics`, `products`, `commissions`, `domain`, `begin_verification`, `verify_domain`, `update_catalog`, `report_event`. При ошибке HTTP выбрасывается `PartnerAPIError` со статусом и текстом.

## Ошибки

Тело ошибки: `{"error": "текст на русском"}`. Заголовок `X-Request-ID` помогает найти запрос в логах.

| HTTP | Смысл |
|---|---|
| 400 | Некорректный JSON, параметры или товар |
| 401 | Ключ или сессия отсутствует, отозвана или истекла |
| 403 | Домен не подтверждён |
| 404 | Ресурс отсутствует |
| 409 | Действие невозможно в текущем состоянии |
| 413 | Слишком большой запрос |
| 429 | Превышен лимит, см. `Retry-After` |
| 503 | Сервис проверки домена временно недоступен |

Не повторяйте неизвестный POST с новым `event_key`: для безопасного повтора используйте прежний.

## Ограничения

| Операция | Лимит |
|---|---|
| Сводка `summary` | 100 запросов в час |
| Страницы каталога и начислений | 120 в час, до 100 записей на страницу |
| Загрузка каталога | 20 в час, до 100 товаров и 64 КБ на запрос |
| Домен, проверка домена, аналитика и события магазина | общий лимит 120 в час |
| Проверка домена | дополнительно не чаще 6 раз за 15 минут |
| Вход в кабинет | 8 попыток за 15 минут с одного IP |

## Безопасность

- Каталог, статистика и начисления разделены по партнёру; чужие данные недоступны.
- Ключи и сессии хранятся только в виде SHA-256-хешей.
- Структура событий фиксирована, произвольные данные отклоняются.
- Ссылки на товары принимаются только на подтверждённый HTTPS-домен.
- Административные методы недоступны с партнёрского домена, действия администраторов фиксируются в аудите.
- Приём платежей за материалы, split-платежи и автоматическое перечисление комиссий пока не поддерживаются.

Обработка данных: [политика партнёрской платформы](/privacy). Условия пилота: [условия](/terms). Эти документы не заменяют подписанный договор.
