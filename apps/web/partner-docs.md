# Smetra Partner API

**Версия:** v1 / пилот · **Домен API:** \`https://console.smetra.online\`  
**Для покупателей:** \`https://smetra.online\`

Интегрируйте сервис создания смет в сайт магазина, публикуйте каталог стройматериалов и анализируйте переходы, регистрации, подтверждённые подписки и клики по товарам.

> Выплаты по партнёрской программе отключены до оформления договоров, налоговой модели и расчётных реквизитов. В консоли доступны только начисления для сверки. Не воспринимайте их как произведённые выплаты.

## Быстрый старт

1. Получите у администрации «Сметры» код партнёра и секретный API-ключ. Ключ выдаётся один раз.
2. Войдите на [console.smetra.online](https://console.smetra.online).
3. Подтвердите домен магазина через **DNS TXT** или **HTML meta-tag**.
4. Разместите партнёрскую ссылку или JavaScript SDK на своём сайте.
5. Через серверный API загрузите каталог материалов.
6. Смотрите аналитику в консоли или через Python SDK.

## Защита ключей и авторизация

Серверные API-запросы используют заголовок:

~~~http
Authorization: Partner smp_live_YOUR_SECRET_KEY
~~~

**Нельзя** передавать API-ключ в JS на сайте, мобильном приложении или URL. Используйте серверную интеграцию или временную сессию в партнёрской консоли.

Консоль обменивает API-ключ на отдельную сессию сроком 1 час:

~~~http
POST /api/partners/console/session
Content-Type: application/json

{"api_key":"smp_live_YOUR_SECRET_KEY"}
~~~

Ответ \`201\`: \`{"session_token":"smp_session_...","expires_in":3600}\`.

Для последующих запросов из консоли:

~~~http
Authorization: PartnerSession smp_session_...
~~~

Сессия автоматически истекает; \`POST /api/partners/console/logout\` отзывает её. Все ответы не кэшируются.

## Подтверждение домена (как в Meta Business)

Подтверждение показывает, что партнёр контролирует заявленный при подключении домен. **Это проверка «Сметры»**, а не Meta/Facebook Business Manager.

### Способ 1: DNS TXT (рекомендуется)

~~~http
POST /api/partners/console/domain
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{"method":"dns"}
~~~

Ответ содержит домен, токен и статус. Для магазина \`store.example.org\` добавьте в DNS:

~~~text
Type: TXT
Name: _smetra-verification.store.example.org
Value: smetra-verify-<выданный токен>
~~~

Затем выполните:

~~~http
POST /api/partners/console/domain/verify
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{}
~~~

Проверка читает публичный TXT-запись через фиксированный DNS-over-HTTPS-резолвер. Распространение DNS может занять некоторое время.

### Способ 2: HTML meta-tag

Создайте запрос с \`{"method":"meta"}\`. Разместите в HTML главной страницы:

~~~html
<meta name="smetra-domain-verification" content="smetra-verify-<выданный токен>">
~~~

Затем вызовите тот же \`POST /domain/verify\`. Требуется HTTPS-страница по **точному домену**, ответ 200 и \`text/html\`; перенаправления не поддерживаются. Верификатор не обращается к частным IP-адресам.

Проверить текущее состояние:

~~~http
GET /api/partners/console/domain
Authorization: Partner smp_live_YOUR_SECRET_KEY
~~~

Без проверки домена товары могут быть импортированы, но **не публикуются** в предложениях «Сметры».

## Реферальные переходы и регистрации

Ссылка партнёра:

~~~text
https://smetra.online/api/partners/r/YOUR_PARTNER_CODE
~~~

При переходе сервер создаёт анонимный идентификатор посещения в HttpOnly-cookie и направляет пользователя к регистрации. После создания **нового** аккаунта и его первого рабочего запроса атрибуция фиксируется сервером.

Существующие аккаунты не переназначаются другому партнёру; тестовые платежи не создают комиссий. Не используйте накрутку или саморефералы.

### JavaScript SDK для сайта магазина

Подключите публичный SDK:

~~~html
<div id="smetra-action"></div>
<script src="https://console.smetra.online/partner-sdk.js"></script>
<script>
  SmetraPartner.mount({
    code: "YOUR_PARTNER_CODE",
    container: "#smetra-action",
    label: "Составить смету бесплатно"
  });
</script>
~~~

Для существующей кнопки \`<a class="smetra-link">...\`:

~~~js
SmetraPartner.attach({code:"YOUR_PARTNER_CODE",selector:"a.smetra-link"});
~~~

SDK не содержит ключей и не отслеживает посетителей скрытно. Засчитывается переход по ссылке на сервер «Сметры».

## Каталог материалов

Импортируются пакеты до **100 товаров за запрос**:

~~~http
POST /api/partners/console/catalog
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{
  "products": [
    {
      "sku": "BLOCK-300",
      "name": "Газобетонный блок 600×300×200",
      "price_kopecks": 17900,
      "url": "https://store.example.org/catalog/BLOCK-300",
      "available": true
    }
  ]
}
~~~

Ссылки обязаны использовать HTTPS **подтверждённого домена** партнёра, без другого порта, логина и пароля. \`sku\` уникален в рамках партнёра. Повторный импорт одного SKU обновляет запись.

Публичные клиентские запросы:

- \`GET https://smetra.online/api/partners/offers?q=газобетон\` — поиск подходящих товаров авторизованным пользователем «Сметры»;
- \`GET https://smetra.online/api/partners/out/{product_id}\` — учтённый переход на сайт магазина.

Оформление заказа пока выполняется на сайте магазина, не внутри «Сметры».

## Аналитика и конверсии

~~~http
GET /api/partners/console/summary
GET /api/partners/console/analytics?days=30
Authorization: Partner smp_live_YOUR_SECRET_KEY
~~~

Доступные периоды: \`7\`, \`30\`, \`90\` дней, группировка по UTC.

\`analytics\` содержит:

| Поле | Значение | Достоверность |
|---|---|---|
| \`visits\` | Переходы по ссылке | Фиксирует сервер |
| \`registrations\` | Новые атрибутированные аккаунты | Фиксирует сервер |
| \`verified_subscription_payments\` | Подтверждённые YooKassa платежи, без тестовых | Проверено платёжным провайдером |
| \`outbound_material_clicks\` | Переходы на товар магазина | Фиксирует сервер |
| \`merchant_reported\` | События сайта и заявки магазина | **Со слов партнёра, не подтверждение оплаты** |
| \`timeline\` | Ежедневные события | UTC |

Денежные значения передаются целыми числами **в копейках**. Никакие сведения о покупателях, их email или других контактах не передаются партнёру.

Консоль умеет экспортировать ежедневную статистику в CSV.

## События интернет-магазина (серверный API)

Чтобы сопоставлять работу виджета и заказы магазина, ваш сервер может присылать обезличенные события:

~~~http
POST /api/partners/console/events
Authorization: Partner smp_live_YOUR_SECRET_KEY
Content-Type: application/json

{
  "event_key": "store-order-2026-000012",
  "event_type": "material_order_reported",
  "amount_kopecks": 259900
}
~~~

Типы: \`widget_impression\`, \`widget_click\`, \`material_order_reported\`.

\`event_key\` — стабильный уникальный ключ события (12–100 символов). Повторы безопасны и не увеличивают счётчики. Для двух типов виджета сумма должна быть 0, для заказа — положительной.

Важно: данные партнёра **не могут** менять конверсии подписок или создавать партнёрские комиссии. Для покупок материалов это лишь источник данных магазина, пока нет отдельной проверки статусов заказов.

Не отправляйте email, телефоны, адреса, IP покупателей или свободный текст с персональными данными.

## Python SDK

В репозитории: \`sdk/python/\`. Для установки из исходников:

~~~bash
pip install -e ./sdk/python
~~~

~~~python
import os
from smetra_partner import PartnerClient

client = PartnerClient(os.environ["SMETRA_PARTNER_API_KEY"])
print(client.analytics(days=30))

client.report_event(
    event_key="order-2026-00000001",
    event_type="material_order_reported",
    amount_kopecks=259900,
)
~~~

SDK использует HTTPS, заголовки авторизации, конечные таймауты и выбрасывает исключения при ошибках HTTP. Секрет хранится **только на сервере**.

## Комиссии и возвраты

Учёт комиссий происходит только после успешной проверки платежа через YooKassa. Повторные платёжные уведомления не создают дублей. Полный возврат аннулирует невыплаченную комиссию.

Модель по умолчанию: **20% с подтверждённого платежа**, до **12 месяцев с первой оплаты**; реальные условия задаются отдельно для каждого партнёра. Есть 30-дневный период ожидания возвратов.

**Автоматические выплаты отключены.** Не создано ни API отправки денег, ни выплатного кошелька. Юридическое оформление, налоги, акты и расчёт с контрагентами — отдельный этап после согласования договора.

## Ошибки и ограничения

| HTTP | Смысл |
|---|---|
| 400 | Некорректный JSON, аргументы или продукт |
| 401 | Отсутствует, отозван или истёк доступ |
| 403 | Домен не подтверждён |
| 404 | Ресурс отсутствует |
| 409 | Проверку нельзя завершить в текущем состоянии |
| 429 | Ограничение частоты запросов, см. \`Retry-After\` |
| 503 | Сервис верификации временно недоступен |

\`X-Request-ID\` помогает сопоставлять ошибки с серверными логами. Не повторяйте неизвестные POST-операции с новым \`event_key\`; используйте прежний ключ для безопасного повтора.

## Приватность, безопасность и развитие

- Каталог и статистика жёстко разделены по \`partner_id\`.
- Токены партнёров и временных сессий в базе хранятся только в виде SHA-256-хешей.
- Структура событий фиксирована; произвольные пользовательские данные запрещены.
- Для товаров действует проверка HTTPS-домена и отдельная проверка его владения.
- Услуги приёма платежей за стройматериалы, split-payments и автоматического перечисления комиссий **пока не поддерживаются**.
- Для будущих интеграций предусмотрены направления: OAuth для enterprise-партнёров, обновление остатков, заказ по готовой корзине, подписанные webhooks и подтверждение статусов заказа.
